Diagnóstico do sistema e propostas de melhoria

Leitura do repositório atual (frontend React, protótipo legado, wrapper Android e o experimento "Modo Campo") para mapear os pontos que mais pesam na experiência hoje — e como resolvê-los sem abandonar o que já está funcionando.

O que existe hoje, em três camadas

frontend/ React + Vite + Tailwind. É o app "de verdade" — Dashboard, TED em detalhe, cadastro. Tipografia IBM Plex, azul institucional, cards e badges consistentes.
index.html raiz Protótipo estático antigo. O próprio ARCHITECTURE.md do repo marca como "não usar em produção" — mas é ele que vira o APK Android (ver achado #1).
mockup-mobile/ Experimento "Modo Campo" — tela pensada para registrar execução em campo, offline-first. Boa ideia, mas isolada: outra tipografia (Fraunces/Nunito), outros ícones (Lucide), sem link nenhum com o app real.

Principais achados

O APK Android empacota a interface errada Alto impacto

scripts/build-www.js copia index.html, app.js e styles.css — exatamente os arquivos que ARCHITECTURE.md lista como legado. O frontend React (o dashboard que os usuários web usam) nunca entra no build do Capacitor. Quem instala o app Android hoje vê um sistema diferente do que existe na web.

Três identidades visuais para um produto só Alto impacto

App real: IBM Plex Sans/Mono + azul #0C447C. "Modo Campo": Fraunces + Nunito Sans + ícones Lucide. Protótipo legado: outra folha de estilo própria. Não existe um token compartilhado entre eles — qualquer peça nova herda uma das três linguagens por acaso, não por decisão.

O dashboard real não se adapta a telas pequenas Médio impacto

globals.css não tem nenhuma @media query. A sidebar é fixa em 228px e o padding de página é 28px fixo — em qualquer viewport. Isso é aceitável para um SPA só-desktop, mas o produto já é empacotado como app Android via Capacitor.

Ícones em emoji no lugar de um sistema visual Médio impacto

Sidebar e alertas usam emoji (📊 📋 ⏰ 💸) como ícone. Renderização varia por sistema operacional e fonte, e não acompanha peso/cor do texto ao redor. O próprio "Modo Campo" já resolveu isso com um pacote de ícones vetoriais — é só uma questão de estender essa escolha para o resto do app.

Navegação lateral muito enxuta para o que o sistema já tem Médio impacto

O menu tem só "Dashboard" e "Novo TED", mas o sistema já tem Login e Registro — ou seja, é multiusuário. Não há um lugar para relatórios, exportação ou configuração de conta, então tudo isso hoje não tem endereço na interface.

Alertas somem ao sair do Dashboard, sem busca global Baixo impacto

Os "Alertas Inteligentes" (TED vencido, orçamento no limite, física × financeira descompassada) são calculados só na tela do Dashboard e não aparecem em nenhum outro lugar do app. Também não existe forma de buscar um TED por número ou título fora da lista principal.

Botões de ação na tela de detalhes sem função Baixo impacto

Em TEDDetails.tsx, os botões "+ Adicionar Marco" e "+ Adicionar Item" existem visualmente mas não têm onClick. A interface promete uma ação que ainda não foi implementada.

O que este canvas propõe

Duas peças ao lado, no mesmo canvas, mostram a direção — sem inventar uma estética nova: os dois mockups usam exatamente os tokens (cores, tipografia, componentes) que já existem em frontend/src/styles/globals.css.

Dashboard — proposta

Busca e sino de notificações no topo, ícones vetoriais no lugar dos emoji, variação vs. mês anterior nos cards, tabela com ordenação e paginação, e menu lateral com Relatórios e Configurações.
